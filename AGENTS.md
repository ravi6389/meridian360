# AGENTS.md — Meridian 360

Governance file for CoCo (Snowflake's data-native coding agent) working in this repo.
Read this before any SQL execution or file change.

## Project

**Meridian 360** — a Customer 360 and Next Best Action engine for a composite
property & casualty insurer. Unifies structured policy/claim/billing data with
unstructured call transcripts and documents, produces a single customer view,
and recommends governed next best actions that can be executed in one click.

## Hard rules

1. **No production data, ever.** Every row in this project is synthetic and
   generated by `python/gen_synth.py`. Names, addresses, phone numbers and
   policy numbers are fabricated. Do not connect to, query, or copy from any
   schema outside `MERIDIAN`.
2. **No DROP or TRUNCATE outside `MERIDIAN`.** Within `MERIDIAN`, `DROP` is
   allowed only on objects this repo created.
3. **Data is frozen after the seed load.** Once `RAW` is populated, do not
   regenerate. Downstream joins and the demo storyline depend on fixed keys.
   If regeneration is unavoidable, rebuild every layer in order.
4. **Writes to external systems require a logged recommendation.** Any Slack,
   Jira or email action must reference a `RECOMMENDATION_ID` that exists in
   `SERVING.NBA_RECOMMENDATION`, and must insert a row into
   `SERVING.ACTION_LOG`. No fire-and-forget side effects.
5. **Suppression rules are not optional.** Code that ranks or surfaces actions
   must apply `SERVING.V_SUPPRESSION` before display. A suppressed action may
   be shown as suppressed, never as recommended.
6. **Every recommendation carries evidence.** A row in `NBA_RECOMMENDATION`
   without populated `REASON_CODES` and at least one `EVIDENCE_REF` is invalid.
7. **PII boundary.** Transcript text may be summarized and classified. Do not
   write raw transcript text into Slack, Jira, or any external payload — send
   the summary and the interaction ID only.

## Conventions

- SQL files are numbered and idempotent. Re-running a file must not error.
- Prefer `CREATE OR REPLACE` for views, `CREATE IF NOT EXISTS` for tables
  holding seeded or logged data (`ACTION_LOG` must never be replaced).
- Dynamic tables use `TARGET_LAG = '1 hour'` in dev, `'20 minutes'` for the demo.
- All timestamps `TIMESTAMP_NTZ`, all money `NUMBER(12,2)`, all scores
  `NUMBER(5,4)` in the range 0–1.
- Surrogate keys are strings with a type prefix: `CUST-00042`, `POL-00310`,
  `INT-002871`.
